# 予約を取り消すのAPI仕様

## 責務

対象予約と後続順位、書籍状態、必要な通知要求を一取引で確定する。

## 契約

| 操作 | 参照 | 認証と認可 |
|---|---|---|
| cancelReservation | [API索引](_api-summary.yaml)のcancelReservation | 本人スコープ |
| getReservation | [API索引](_api-summary.yaml)のgetReservation | 本人スコープ |
| getBook | [API索引](_api-summary.yaml)のgetBook | 本人スコープ |

## 実行条件

| 判断 | 処理 |
|---|---|
| 取消の再要求 | 同一キーは前回結果を返す。新しいキーで既に取消済みの対象を指定した場合も取消状態を200で返し、順位とイベントを再更新しない。終了済みは422。 |
| 先頭の交代 | 予約待ち書籍で先頭が変わり、次の有効予約があるときは返却通知の同一受付処理で要求を保存する。全予約がなくなれば書籍を在庫ありへ更新する。 |
| 過去要求 | 取消対象の未公開通知要求は配信対象外にし、公開済みの要求もworkerが送信前に状態を再確認する。 |

## データ操作

[_model-summary.yaml](_model-summary.yaml)を参照する。
本人所有を確認し、書籍と全有効予約をロックする。
予約取消、後続順位更新、必要な書籍状態更新、次の先頭への通知要求を同一SQLトランザクションで確定する。

## 再送と競合

| ケース | 処理と結果 |
|---|---|
| 共通保証 | [技術規則](../../../_cross-cutting/technical-rules.md)の認証、日時、トランザクション、再送を適用する |
| 対象不在 | 404を返す。本人スコープの不一致も同じ応答とする |
| version不一致 | 409を返し、変更せず最新値を再取得させる |
| commit前の障害 | 同じ取引の変更をrollbackする |
| commit後の応答不明 | 同じキーと入力の再送で確定済み結果を返す |
