## USDM 受け入れ基準 ↔ UC 対応表

`docs/usdm/latest/requirements.yaml` の `specifications[].acceptance_criteria[]` と UC を
機械可読に結びつける。dist-impl はこの表と各 UC の「受け入れ基準トレーサビリティ」表の
2 段引きで、文字列推測もユーザー確認もなしに ATDD シナリオを一意に選択できる。

### 受け入れ基準 ID の付与規則

- 形式: `{仕様ID}#{n}`（例: `SPEC-002-01#1`）。`n` は `acceptance_criteria` 配列の
  **1 始まりの添字**であり、YAML 上の並び順が正本となる。
- USDM 側に ID 列は持たない（USDM は requirements スキルの所有物であり、spec スキルが列を追加しない）。
  順序が変わると ID が変わるため、`acceptance_criteria` の並び替え・途中挿入は行わず、追加は末尾に行う。
- 1 つの受け入れ基準は **主担当 UC を必ず 1 つだけ**持つ。主担当 UC の BDD Scenario が

### UC 側の記法（全 UC 共通）

各 UC の `spec.md` に「受け入れ基準トレーサビリティ」節を置き、次の表を書く。

```markdown
## 受け入れ基準トレーサビリティ

| 受け入れ基準 ID | 役割 | 対応する BDD Scenario |
|---|---|---|
| SPEC-002-01#1 | 主担当 | 在庫ありの書籍を登録済み利用者へ貸し出せる |
| SPEC-002-01#2 | 主担当 | 貸出中の書籍への貸出登録は拒否される |
```

- 「対応する BDD Scenario」には当該 UC の `spec.md`「E2E 完了条件（BDD）」の
  **Scenario 名を一字一句そのまま**書く（ティア側 BDD ではなく E2E 側を参照する）。
- **1 セルに 1 つの Scenario 名だけ**を書く。`/` や読点で複数名を連結しない
  （連結すると機械的な一意選択が成立しない）。
- 1 つの基準に複数の Scenario が対応する場合は、同じ基準 ID の行を Scenario の数だけ並べる。
  1 つの Scenario が複数の基準を満たす場合も行を分けて同じ Scenario 名を繰り返す。
- 主担当を持たない UC でも、上表に**補助として現れる基準は `補助` 行で列挙する**。
  上表に主担当としても補助としても一切現れない UC だけが
  `| — | 補助専任 | （当該 UC の E2E シナリオ全件） |` の 1 行を書く。
