# 画面状態の接続

| 接続対象 | 正本 | ページが供給する値 |
|---|---|---|
| 外枠 | [PortalShell](../../../../design/latest/storybook-app/src/components/ui/PortalShell.tsx) | portal、currentPath、title、認証済みのuserName |
| 画面構成 | [ScreenMapping](../../../../design/latest/storybook-app/src/docs/ScreenMapping.mdx) | 対象UCのAPI結果と操作callback |
| 読込と失敗 | [Feedback Stories](../../../../design/latest/storybook-app/src/components/ui/Feedback.stories.tsx) | 読込中はLoadingBlock、通信失敗はAlertと再取得操作 |
| 色と余白 | [DesignTokens](../../../../design/latest/storybook-app/src/docs/DesignTokens.mdx) | テーマの選択 |

| 通信状態 | ページの処理 | 表示 |
|---|---|---|
| 初回取得中 | 完了した要求だけ結果を採用する | LoadingBlock |
| 取得成功で0件 | 空配列を渡す | 部品の空状態 |
| 取得失敗 | 元の検索条件を保持する | Alertと再取得操作 |
| 送信中 | 同じ操作の再送キーを保持し、連打を抑止する | submittingまたはloading |
| 送信成功 | 関連照会を無効化して再取得する | 成功結果 |
| 競合 | 最新状態を再取得し、利用者が内容を確認する | 競合理由 |
| 応答不明 | 同一入力と同一キーで結果を確認する | 結果確認中 |

API項目を部品へ渡す変換と送信先は各UCのpresentation仕様を参照する。


<a id="UI-READ"></a>

## UI-READ 取得状態と応答の採用

適用対象はAPIで照会するページとする。
入力元、照会operation、使用する応答フィールドは各UCのpresentation仕様で指定する。

| 状態または契機 | Pageの処理 | 表示 |
|---|---|---|
| 初回読込 | URLの識別子または確定条件で要求を開始 | loading。確認に必要な値を取得するまで確定操作を停止 |
| 要求中の対象や条件変更 | 要求世代を更新し、旧要求を中止またはその応答を破棄 | 新しい要求の読込表示 |
| 最新要求が成功 | 結果を採用。空配列は成功した0件として扱う | 通常表示または空状態 |
| 取得失敗 | 対象と確定条件を保持。古い値は更新操作の根拠に使わない | Alertと同じ条件での再取得操作 |
| 401 | 再認証へ進み、成功後に対象を再取得 | 認証画面 |
| 403/404 | 対象の操作を終了 | 権限不足または対象なし |

一覧の確定検索条件とpage/page_sizeはURLが所有する。
入力中の条件はPageが保持し、確定時にURLへ反映してpageを1に戻す。
古い要求の応答は、後から成功した検索結果を上書きしない。

<a id="UI-WRITE"></a>

## UI-WRITE 送信状態と結果確認

適用対象は更新operationを呼び出すページとする。
対象operation、本文への変換、成功後の画面、無効化する照会は各UCで指定する。
要求の同一性とサーバー側の結果保持は[TR-IDEMP](../technical-rules.md#tr-idemp-再送と結果の回復)を適用する。

1. 確定操作で本文、対象、query、必要なIf-Match、UUIDの要求キーを固定する。
2. Pageがsubmittingを所有し、部品のsubmittingへ渡す。ハンドラでも同じ送信の重複起動を拒否する。
3. Formは送信中にfieldsetをdisabledにする。確認パネルは確定操作を停止する。
4. 成功が確定したら送信情報を破棄し、UCが指定する照会を無効化して再取得する。

| 結果 | 処理と次の状態 |
|---|---|
| 400/422 | 編集値を保持し理由を表示する。入力修正後の別要求には新しいキーを使う |
| 409 VERSION_CONFLICT | 既存対象を再取得し、編集差分または削除対象を再確認する。確認後だけ新キーと最新If-Matchで操作する |
| 409 IDEMPOTENCY_CONFLICT | 元の送信スナップショットで結果を照合する。未確認の元要求が残る間は新キーを作らない |
| 通信切断/503 | 成功と扱わず、固定した同一要求で再送して結果を確認する |
| 401 | 再認証する。同じ主体であることを確認してから同一要求を照合する |
| 403/404 | 既存対象の操作を終了する。結果確認中の要求は新しい対象へ転用しない |

送信スナップショットはタブと認証主体ごとにsessionStorageへ保存する。
再読込時に未確認の要求があれば、その結果を照合してから新しい入力へ進む。
成功、明確な入力拒否後に別要求へ移る時、ログアウト時に保存情報を破棄する。
ログアウトで未確認情報を破棄する場合は、次の登録前に一覧から既存結果を確認するよう案内する。
識別子以外の入力や連絡先をURL、ログ、localStorageへ保存しない。
取消は送信前に行い、送信中または結果不明中の取消をサーバーのrollbackとして扱わない。
