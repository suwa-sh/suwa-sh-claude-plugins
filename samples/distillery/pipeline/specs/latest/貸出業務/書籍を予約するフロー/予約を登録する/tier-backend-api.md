# 予約を登録するのAPI仕様

## 責務

利用者と書籍を直列化し、有効予約の末尾順位を割り当てる。

## 契約

| 操作 | 参照 | 認証と認可 |
|---|---|---|
| createReservation | [API索引](_api-summary.yaml)のcreateReservation | 本人スコープ |
| getBook | [API索引](_api-summary.yaml)のgetBook | 本人スコープ |

## 実行条件

| 判断 | 処理 |
|---|---|
| 本人の特定 | 利用者番号は検証済み認証情報から取得する。要求本文に第三者の利用者番号を受け付けない。 |
| 受付時刻 | 書籍ロック取得後にDB時刻を受付日時とし、同時刻の場合は予約IDの昇順で確定する。順位は有効予約の件数+1。 |
| 状態 | 予約作成は書籍状態を変更しない。返却と同時の場合は書籍ロック後の状態で条件を再評価する。 |

## データ操作

[_model-summary.yaml](_model-summary.yaml)を参照する。
利用者行→書籍行をロックし、利用者のdeleted=falseと対象書籍、有効予約を再確認する。
本人の予約作成と受付イベント追記を同一SQLトランザクションで確定する。

## 再送と競合

| ケース | 処理と結果 |
|---|---|
| 共通保証 | [技術規則](../../../_cross-cutting/technical-rules.md)の認証、日時、トランザクション、再送を適用する |
| 対象不在 | 404を返す。本人スコープの不一致も同じ応答とする |
| commit前の障害 | 同じ取引の変更をrollbackする |
| commit後の応答不明 | 同じキーと入力の再送で確定済み結果を返す |
