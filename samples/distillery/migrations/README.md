# dist-migreのガイド適用例

これは移行計画の例です。新しいスキルによる出力全体の移行実行を検証済みとするものではありません。

## 通常の使い方

旧outputを保持してskillsを新版へ差し替えた後、`distillery:dist-migre`を呼び出します。移行先版の指定は不要で、plugin.jsonから取得します。
実装outputも対象なら、その後に`distillery-impl:dist-impl-migre`へ移行記録と更新済みspecを渡します。

## 1.13.5 → 1.14.0

入力例はコミット`0501dd0`の公開pipelineサンプルを基にします。APIの入口と編集ファイルは種類別ディレクトリへ分かれる前の配置です。
移行後の構成は[現在の公開API](../pipeline/specs/latest/_cross-cutting/api/)を参照してください。

| 項目ID | 判定 | 理由・LLMが行う作業 |
|---|---|---|
| API-DIRECTORIES | 適用予定 | 入口から参照を辿り、HTTPと非同期の編集ファイルを分類する。catalog、相対参照、UC・tier・READMEのリンクを更新する |
| REPO-ONLY | 対象外 | pluginリポジトリの開発用資料・テスト配置の変更。利用者の出力を変えない |
| MIGRATION-GUIDE | 対象外 | スキル追加。利用者の出力契約は変わらない |

LLMはAPI正本を移す前に、両契約が同じschemaファイルを参照していないか調べます。
移動後はbundleとUC sliceを再生成し、型・制約・認可・エラー・送受信操作を比較します。
過去イベントは保持し、検証した変更を新イベントとlatestへ反映します。

この範囲では、UC本文の簡潔化やRDB分割を最初からやり直しません。
現物に以前の移行漏れがあれば、その証拠と追加対象を計画へ記録します。

## 複数版をまたぐ場合

1.9.4 → 1.14.0では、[対応表](../../../plugins/distillery/skills/dist-migre/references/migration-catalog.md)の全変更点を検討します。
契約と所有元を先に確認し、その後で本文の重複を整理します。元の仕様から必要な情報が失われていないことをLLMが照合します。
表の形式やリンクが整っていても、参照先の業務条件が不足していれば要確認として残します。

## この例の確認範囲

- 導入版によるガイド選択と、変更なし項目の除外を確認した。
- 既存のAPI分割テストで、新ディレクトリへの移動前後のbundle一致を確認している。
- 本例では新イベント作成、上流への還流、アプリ実装は実施していない。
