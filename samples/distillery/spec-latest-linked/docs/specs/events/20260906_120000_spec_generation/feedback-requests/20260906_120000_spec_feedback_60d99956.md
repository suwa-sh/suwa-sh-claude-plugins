## CR-60d99956-001: 貸出期間の日数と利用者区分対応をRDRAで定義する

- severity: spec-gap
- related_ids: [RDRA-LOAN-PERIOD]
- related_files: [docs/rdra/latest/条件.tsv, docs/rdra/latest/バリエーション.tsv]

### 観測した事実

条件の返却期限設定条件は日数加算を要求する。バリエーションは利用者区分と貸出期間区分の名前のみで、日数・対応表がない。designページStoryには独自の固定日数と一般利用者の長期制限がある。

### 現在の仕様と問題

貸出期限と利用可能な期間区分を追加判断なしに計算できない。Storyのサンプル値を業務条件に転用すると正本が分散する。

### 変更してほしいこと

RDRA latestに各区分の日数、利用者区分との適用対応、選択不可の場合を定義する。Storyの例から業務値を逆算しない。

### 完了条件

貸出登録と貸出可否照会の期限計算・分岐・BDD、および窓口ページStoryが同じRDRA条件を参照して一意に決まる。

## CR-60d99956-002: 予約待ちと取置き対象者の貸出条件の優先順位を確定する

- severity: spec-gap
- related_ids: [RDRA-LOAN-ELIGIBILITY]
- related_files: [docs/rdra/latest/条件.tsv, docs/rdra/latest/状態.tsv]

### 観測した事実

貸出可否条件は予約待ちを拒否する一方、取置き中書籍貸出条件は対象者を許可し、状態.tsvにも予約待ちからの貸出遷移が存在する。

### 現在の仕様と問題

同一入力に許可と拒否の両方が適用できる。

### 変更してほしいこと

RDRA latestで例外優先順位と対象予約の決定条件を明記する。

### 完了条件

予約待ちの対象者/非対象者で分岐が一意に決まり、登録・可否照会・予約参照のシーケンスとBDDを再検証できる。

## CR-60d99956-003: 利用可能と利用者状態の対応を確定する

- severity: spec-gap
- related_ids: [RDRA-USER-STATE]
- related_files: [docs/rdra/latest/条件.tsv, docs/rdra/latest/状態.tsv]

### 観測した事実

貸出可否条件は利用者状態区分「利用可能」を要求する。状態.tsvの利用者状態は登録済みと取引進行中であり利用可能はない。

### 現在の仕様と問題

登録済みだけか、取引進行中も貸出可能かを決められない。

### 変更してほしいこと

RDRA latestで利用可能の意味と既存状態への対応、既存取引を持つ利用者の扱いを定義する。

### 完了条件

登録と可否照会が全利用者状態に対して一意の結果を返せ、利用者状態遷移とBDDが矛盾しない。

## CR-60d99956-006: DB確定後のKVS障害に対する冪等応答回復を確定する

- severity: spec-gap
- related_ids: [ARCH-SR-013, ARCH-SR-025, ARCH-CTP-006]
- related_files: [docs/arch/latest/arch-design.md]

### 観測した事実

SR-013はKVSへ冪等キーを記録して前回応答を返す。SR-025はRDBの冪等列UNIQUEを要求する。両ストアの途中障害時の前回応答復元は記述されていない。

### 現在の仕様と問題

RDB commit後KVS記録前の停止で重複防止と同じ応答再送を両立する永続データ・照合順序が未定義である。

### 変更してほしいこと

arch latestで原子的に保存するデータ、正データとKVSの役割、応答の復元、保持期間内/期限外の再送結果を定義する。無期限化を既定の解決策としない。

### 完了条件

貸出登録・その他更新UCのモデル/契約/画面再送が同じ回復規則を参照し、commit前後およびKVS障害の受入条件が決まる。
