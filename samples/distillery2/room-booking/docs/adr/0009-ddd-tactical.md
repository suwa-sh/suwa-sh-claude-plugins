# 背景

業務のルールは 3 つの条件 (重なりの判定・予約時刻の妥当性・取り消しの可否) と 2 状態の遷移で、数は少ない。ただし「二重に予約できない」「本人・開始前・予約済みのときだけ取り消せる」という破れてはいけない決まりがある。受入基準は現在時刻を固定して判定する。

# 決定

- 軽量に使う (集約・値オブジェクト・リポジトリ。ドメインイベントの購読の仕組みは作らない)。
- 集約は「予約」1 つ。予約の作成 (時刻の妥当性と過去でないことの確認) と取り消し (本人・開始前・予約済みの確認) を集約のメソッドにする。
- 値オブジェクト: 時間帯 (開始・終了。30 分刻みと開始 < 終了を生成のときに検証。半開区間で重なりを判定)・予約 ID・会議室 ID・社員 ID。
- 会議室は集約にせず、予約から ID で参照する読み取り専用のマスタにする。
- 「同じ会議室の枠が既に埋まっている」の最終判定は DB の一意制約が担う (データストアの決定)。集約は 1 件の予約の中の決まりだけを守る。
- 現在時刻は引数で渡し、domain を純粋に保つ。

# 却下した案

- フル (ドメインイベントを購読して後続の処理を動かす): 後続の処理 (通知・集計) が無い。
- 使わない (トランザクションスクリプト): 取り消しの可否や時間帯の検証が usecase に散り、単体で確かめにくい。
- 会議室を集約にして、会議室の中に予約を持たせる (会議室の集約で重なりを守る): 会議室ごとに全予約を読み込む形になり、同時の予約の衝突が会議室の単位で起きる。DB の一意制約のほうが単純に守れる。

# 影響

- 時間帯と取り消しの決まりは domain の単体テストだけで確かめられる。
- 重なりの決まりは、集約 (1 件の検証) と DB (枠の占有) の 2 か所に分かれる。空き状況の表示の重なりの判定は時間帯の値オブジェクトを使う。
