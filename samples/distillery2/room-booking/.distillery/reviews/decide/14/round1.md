## (2) 指摘

### 指摘 1
- **perspective**: P1
- **対象**: `docs/adr/0007-testing-strategy.md:18`、`:41`、`:53`
- **severity**: medium
- **claim**: Web 画面で空きを見て予約・取消するという要求に対し、受入テストは画面の操作と API の結線を確認しない方針になっている。
- **evidence**: 原文は空き状況を「Web 画面で見られる」ことを求める（`docs/input/要望-20261104.md:5`）。ADR 0007 は API ドライバを使いブラウザドライバを使わないと定め、ボタンが API を呼ばない等の誤りは受入では見つからないと明記する。
- **why_raised**: 画面の結線が誤っている場合、API と画面部品の確認が通っても、社員は要求された予約操作を完了できない。
- **suggested_fix**: 主要な画面操作から API 応答までを確認する少数の受入シナリオを加えるか、同等の結線確認方法を決定に明記する。

### 指摘 2
- **perspective**: P3
- **対象**: `docs/adr/0016-backup-point-in-time-recovery.md:32`、`:36`、`:55`、`docs/adr/_review-summary.md:98`
- **severity**: medium
- **claim**: DB 本体を失っても通知済みの予約・取消を一件も失わない水準と、別保管場所への同期書き込みを採用済みにしているが、この水準と可用性上の代償を受け入れるかが確認の問いとして返されていない。
- **evidence**: ADR 0016 は目標復旧地点を「人への確認の推奨で決定済み」と記し、別保管場所へ書けない間は予約と取消を受け付けないと定める。確認事項の 12 番は変更と影響を説明する記述で、採否を尋ねていない。原文の規模は 5 部屋・数十人である（`docs/input/要望-20261104.md:10`）。
- **why_raised**: 別保管場所が停止した際、社員全員の予約と取消が止まる。小規模な社内業務でこの復旧水準を優先するかは、運用上の判断を伴う。
- **suggested_fix**: データ損失ゼロの対象障害と、同期先の停止中に更新を止める方針を受け入れるか、明示的な確認事項にする。
