### 指摘 1
- **perspective**: P1
- **対象**: `docs/adr/0007-testing-strategy.md:35-54`、`docs/rules/testing.md:50-59`
- **severity**: medium
- **claim**: Web 画面での表示を求める受入基準に対し、受入テストはブラウザを使わず API と画面の入口関数で判定する方針になっている。実際の画面で表示・操作できることが受入では確認されない。
- **evidence**: `docs/requirements/requirements.md:10-16` は画面での空き状況、理由、自分の予約一覧の表示を定める。ADR 0007 はブラウザでの受入を行わず、画面の結線の誤りは受入では見つからないと明記する。
- **why_raised**: 画面と API の結線や描画に誤りがある場合、社員は主要な予約業務を Web 画面で完了できないまま、受入ゲートを通過しうる。
- **suggested_fix**: 主要な画面経路について、実画面の表示と操作を確認する受入条件を追加する。

### 指摘 2
- **perspective**: P1
- **対象**: `docs/nfr/nfr-grade.md:99-106`（D.2.1.1、D.4.1.2、D.5）
- **severity**: medium
- **claim**: 既存の表計算ファイルからの切り替えで、将来の予約を移さず社員に予約し直してもらう案には、既存予約を新システムの空き判定へ反映しきる条件がない。
- **evidence**: 原要望 `docs/input/要望-20261104.md:3-10` は既存の表計算ファイルで予約を管理しているとする。非機能グレードは一括切り替え、予約し直し、移行判定基準なしを置いている。この案が仮置きであることは `docs/adr/_review-summary.md:82` で確認事項になっている。
- **why_raised**: 切り替え時に予約し直されていない既存予約があると、その時間帯が新システムでは空きと表示され、別の社員が予約できる。原要望の二重予約解消に直接影響する。
- **suggested_fix**: 切り替え前に既存の将来予約を全件反映する方法と、反映完了を確かめる判定基準を決める。
