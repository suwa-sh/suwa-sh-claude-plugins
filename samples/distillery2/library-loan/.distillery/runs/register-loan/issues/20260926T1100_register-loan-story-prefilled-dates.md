## 事実

- 構造の正である story `packages/ui/stories/LoanRegister.stories.tsx` の Default (登録前) は、「貸出の内容」に次の値を表示している。
  - 貸出日: `TODAY` (41-42 行目)
  - 返却期限: `2026-10-10` (43-44 行目)
- 契約 `POST /loans` (registerLoan) は、どちらもサーバーが決める値と定めている。
  - 「貸出日はサーバーの当日の日付とし、返却期限は貸出日に貸出期間を加えた日を自動で設定する」
  - 「貸出期間の日数は要求に値が無く、この契約では固定しない」
  - `RegisterLoanRequest` は「貸出日はサーバーの当日の日付で決まるため要求に含めない」
- 登録前に貸出日と返却期限を取得する operation は、契約に無い。
- このため frontend は、登録前の貸出日と返却期限を仕様どおりに表示できない。
  - 端末の日付で貸出日を出すと、サーバーの当日と食い違う可能性がある。
  - 返却期限は貸出期間が未定のため、画面では算出できない。

## 実装側の対応 (暫定)

| 状態 | 貸出日 | 返却期限 |
|---|---|---|
| 登録前 (Default) | 行は出し、値は空欄 | 行は出し、値は空欄 (注記「自動で決まります」は表示) |
| 登録後 (Completed) | 応答の `loan.loanedOn` | 応答の `loan.dueDate` |

- 行の構成 (利用者 / 書籍 / 貸出日 / 返却期限) は story と揃えた。
- 登録前を空欄にする判断は、AssumptionRecord A-006 に記録した。

## 求める変更 (どちらかを選ぶ)

1. story の Default から、貸出日と返却期限の値を外す (「登録すると決まります」等の文言にする)。
2. 登録前に貸出日と返却期限を得る手段 (見積り用の operation など) を要求と契約に追加する。

- 1 なら frontend の変更は不要か、文言の追加だけで済む。
- 2 なら frontend はその operation を呼んで Default に値を出す。
