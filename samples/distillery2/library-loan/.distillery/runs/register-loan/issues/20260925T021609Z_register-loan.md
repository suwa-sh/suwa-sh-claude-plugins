## 事実

- 画面見本 `packages/ui/stories/LoanCheckout.stories.tsx` の Error 状態は、次の 2 つを出す。
  - お知らせ (Alert): title「貸し出せません」、detail「この蔵書は他の利用者向けに取り置き中です。」
  - 蔵書ID欄の項目エラー: 「在庫ありか、この利用者向けに取り置き中の本だけ貸し出せます」
- 契約 `createLoan` の 409 (examples `onLoan` / `heldForOther`) は `code` / `title` / `detail` だけを持つ。
  `errors[]` (FieldError) が無いため、どの項目の問題かを応答から判断できない。
- 項目エラーの文言「在庫ありか、この利用者向けに取り置き中の本だけ貸し出せます」は契約・要求・シナリオのどこにも無い。
- scaffold の単体テスト `apps/frontend/src/register-loan.test.ts` は、409 の表示状態を `{ kind, title, detail }` だけと定めている。
- `docs/rules/tier-frontend.md` は story を構造の正とし、乖離は実装で曲げず issues → 還流で変更要求すると定める。

## 両立しない理由

- 見本どおりに蔵書ID欄へ項目エラーを出すには、画面が次のどちらかをする必要がある。
  - `code: loan_not_allowed` を蔵書ID欄へ固定で結びつけ、契約に無い文言を画面が持つ
  - 契約に無い `errors[]` を期待する
- どちらも契約・scaffold テストと矛盾する。

## 実装の現状 (契約どおり)

- 409 は Problem の title / detail をお知らせに出す。
- 項目エラーは応答に `errors[]` があるときだけ出す (400 と同じ写像 `copy_id` → 蔵書ID欄)。
- そのため契約の 409 に `errors[]` が加われば、画面の変更なしに見本どおりの表示になる。

## 求める対応 (⭐推奨を先頭に)

1. ⭐ 契約の 409 examples に `errors: [{ field: "copy_id", code: "loan_not_allowed", message: "..." }]` を加える。
   backend-api も同じ項目を返す。scaffold テストの 409 の期待値も合わせて更新する
2. 画面見本の Error 状態から蔵書ID欄の項目エラーを外し、お知らせだけにする (design の変更)
