| ID | 要求 | 仕様 | 理由（背景） | 説明 |
|----|------|------|------------|------|
| REQ-001 | 図書館の蔵書を一元管理し、目的の書籍を検索できるようにしたい | | 書籍情報が紙台帳と表計算ファイルに分散しており、司書の管理の手間とミスが発生しているため | |
| SPEC-001-01 | | 司書は書籍情報（タイトル、著者、ISBN、出版社、ジャンル等）を登録・編集・削除できる | | 1. Given 司書が書籍登録画面を開いている When タイトル・著者・ISBN・出版社・ジャンルを入力して登録する Then 書籍が蔵書として登録され一覧に表示される<br>2. Given 登録済みの書籍がある When 司書が書籍情報を編集して保存する Then 変更後の書籍情報が表示される<br>3. Given 貸出されていない登録済みの書籍がある When 司書が書籍を削除する Then 書籍は蔵書一覧と検索結果に表示されなくなる |
| SPEC-001-02 | | 書籍をキーワード、タイトル、著者、ISBN、ジャンルで検索できる | | 1. Given 蔵書が登録されている When 利用者または司書がキーワードで検索する Then キーワードを含む書籍の一覧が表示される<br>2. Given 蔵書が登録されている When タイトル・著者・ISBN・ジャンルのいずれかを指定して検索する Then 指定条件に一致する書籍だけが表示される |
| REQ-002 | 図書館の利用者情報を一元管理したい | | 利用者情報が紙台帳と表計算ファイルに分散しており、貸出・予約・通知の前提となる利用者の特定と連絡に手間とミスが生じているため | |
| SPEC-002-01 | | 司書は利用者情報（氏名、連絡先、利用者番号等）を登録・編集・削除できる | | 1. Given 司書が利用者登録画面を開いている When 氏名と連絡先を入力して登録する Then 一意の利用者番号が付いた利用者が登録される<br>2. Given 登録済みの利用者がいる When 司書が連絡先を編集して保存する Then 変更後の連絡先が以後の通知に使われる<br>3. Given 貸出中の書籍がない利用者がいる When 司書が利用者を削除する Then 利用者は利用者一覧に表示されなくなる |
| REQ-003 | 書籍の貸出・返却を Web 画面から行えるようにしたい | | 貸出・返却の管理を司書が手作業で行っており、手間とミスを減らしたいため | |
| SPEC-003-01 | | 司書は Web 画面で利用者と書籍を指定して貸出を登録し、書籍は貸出中になる | | 1. Given 在庫ありの書籍と登録済みの利用者がいる When 司書が貸出を登録する Then 貸出が記録され書籍の状態が貸出中になる<br>2. Given 貸出中の書籍がある When 司書が同じ書籍の貸出を登録しようとする Then 貸出できない旨が表示され貸出は記録されない |
| SPEC-003-02 | | 司書は Web 画面で書籍の返却を登録し、貸出が完了して書籍は在庫あり（予約がある場合は予約待ち）になる | | 1. Given 予約のない貸出中の書籍がある When 司書が返却を登録する Then 貸出が返却済みになり書籍の状態が在庫ありになる<br>2. Given 予約のある貸出中の書籍がある When 司書が返却を登録する Then 貸出が返却済みになり書籍の状態が予約待ちになる |
| REQ-004 | 貸出中の書籍を Web 画面から予約でき、返却されたら予約者に知らせたい | | 予約の管理を司書が手作業で行っており、予約順の管理や連絡の手間とミスを減らして利用者サービスを向上させたいため | |
| SPEC-004-01 | | 利用者は Web 画面で貸出中の書籍を予約でき、予約は受付順に予約順位が付く | | 1. Given 貸出中の書籍がある When 利用者が予約する Then 予約が受け付けられ受付順の予約順位が付く<br>2. Given 在庫ありの書籍がある When 利用者が予約しようとする Then 予約できない旨が表示され予約は記録されない |
| SPEC-004-02 | | 予約のある書籍が返却されたら、予約順 1 位の利用者にメールで通知する | | 1. Given 予約順 1 位の利用者がいる書籍が貸出中 When 司書がその書籍の返却を登録する Then 予約順 1 位の利用者の連絡先に返却通知メールが送信される<br>2. Given 予約のない書籍が貸出中 When 司書がその書籍の返却を登録する Then 返却通知メールは送信されない |
| REQ-005 | 貸出期限の管理と延滞者への通知を自動化したい | | 期限管理と延滞者への連絡を司書が手作業で行っており、手間と連絡漏れを減らしたいため | |
| SPEC-005-01 | | 貸出登録時に返却期限を自動で設定する | | 1. Given 在庫ありの書籍と登録済みの利用者がいる When 司書が貸出を登録する Then 貸出日から貸出期間を加えた日が返却期限として設定される |
| SPEC-005-02 | | 返却期限が近づいた貸出の利用者に、リマインドメールを自動送信する | | 1. Given 返却期限までの日数がリマインド日数以内の未返却の貸出がある When 日次の期限チェックが実行される Then 利用者の連絡先にリマインドメールが 1 回送信される |
| SPEC-005-03 | | 返却期限を超過した貸出の利用者に、督促メールを自動送信する | | 1. Given 返却期限を超過した未返却の貸出がある When 日次の期限チェックが実行される Then 貸出の状態が延滞になり利用者の連絡先に督促メールが送信される |
| REQ-006 | 利用者が自分の貸出履歴と予約状況を Web 画面で確認できるようにしたい | | 利用者が司書に問い合わせずに自分の利用状況を把握できるようにし、利用者サービスを向上させたいため | |
| SPEC-006-01 | | 利用者は Web 画面で自分の貸出履歴（現在の貸出と過去の貸出）を確認できる | | 1. Given 利用者に現在の貸出と過去の貸出がある When 利用者が貸出履歴画面を開く Then 現在の貸出と返却期限、過去の貸出が区別して表示される<br>2. Given 他の利用者の貸出がある When 利用者が貸出履歴画面を開く Then 自分以外の利用者の貸出は表示されない |
| SPEC-006-02 | | 利用者は Web 画面で自分の予約状況（予約中の書籍と予約順位）を確認できる | | 1. Given 利用者に予約中の書籍がある When 利用者が予約状況画面を開く Then 予約中の書籍と現在の予約順位が表示される |
| REQ-007 | 司書が在庫状況や貸出の傾向をレポートとして把握できるようにしたい | | 在庫状況や人気・利用傾向を把握して蔵書の運用判断に活かしたいが、手作業では集計の手間が大きいため | |
| SPEC-007-01 | | 司書は書籍ごとの在庫状況（貸出中・在庫あり・予約待ち）をレポートで確認できる | | 1. Given 貸出中・在庫あり・予約待ちの書籍がある When 司書が在庫状況レポートを開く Then 状態ごとの書籍と件数が表示される |
| SPEC-007-02 | | 司書は貸出回数に基づく人気書籍のランキングをレポートで確認できる | | 1. Given 書籍ごとに貸出実績がある When 司書が人気書籍ランキングを開く Then 貸出回数の多い順に書籍が並んで表示される |
| SPEC-007-03 | | 司書は指定した期間の貸出統計をレポートで確認できる | | 1. Given 複数期間にわたる貸出実績がある When 司書が期間を指定して貸出統計を開く Then 指定期間内の貸出件数が集計されて表示される |
| REQ-008 | 将来的に電子書籍にも対応できるようにしておきたい | | 将来の電子書籍の取り扱い開始時に、蔵書管理の仕組みを作り直さずに済むようにしたいため | |
| SPEC-008-01 | | 書籍情報は媒体種別（紙の書籍・電子書籍）を持ち、媒体種別を追加できる構造にする | | 1. Given 司書が書籍登録画面を開いている When 媒体種別に紙の書籍を指定して登録する Then 書籍が媒体種別つきで登録される<br>2. Given 媒体種別が紙の書籍である書籍が登録されている When 書籍情報を表示する Then 媒体種別が表示される |
