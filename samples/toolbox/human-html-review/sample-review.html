何が変わったか

前は 6 つの枠と 3 枚の図が必ず要求され、内容が枠に合わないときも埋める必要があった。後は必須を 3 つに減らし、間は「読者が次に何を知りたいか」で決める。 確認済み

表の内容は書き直した手引きと検査スクリプトの記述で確認した。 確認済み

要望実現した場所具体的に
枠にはめず、内容を都度考える説明書 / 方法論固定セクションを廃止。「読者の問いの階段」を書き出してから組む手順にした
読者は文脈を忘れている必須部品「いま何の話か」を最初の画面に必須化。何の作業・いまどこ・なぜ聞く、の 3 点と現在地マップ
専門用語より平易な表現方法論 / 検査言い換え表を用意。初出で 1 行説明する規則
内部 ID ではなく名前方法論 / 検査「大文字 + ハイフン + 連番」や 16 進の並びのような ID を本文から検出して警告。対応表は付録にだけ置く
テクニカルライティング方法論一文一義、結論を先に、同じものは同じ名前で、段落は 3 文まで
文章よりリスト・表・構造方法論 / 検査「見せ方の優先順位」を図 → 表 → リスト → 文と定義。長い段落を警告
文章より図解、図の割合を増やす図の手引き / 検査問いごとの図の型を用意。見出し 2 つに図 1 つ未満なら警告
横幅を広く部品の見た目本文幅の上限を 1180px から 1760px に広げ、図と説明を横に並べる部品を追加

気になる所と、まだ確かめていないこと

大きな対象で使うと重くなるかもしれない: 図を増やす方針なので、判断材料が 10 個を超える対象では図の枚数も増える。前の方式で 140KB 級のページが出ていた実績があり、同程度になる可能性がある。 推測
内部 ID の検出は誤検知がある: 「大文字 + ハイフン + 数字」と「16 進の並び」で機械判定している。製品名 (例: S3) は除外リストで逃がしたが、漏れは残る。警告止まりにしてあるので、作業は止まらない。 確認済み
他のスキルへの影響は無い: このスキルを呼ぶ側 (中ハーネス展開スキルと、ユーザー共通指示のプランモード規則) は名前だけを参照しており、削除した「承認 / 選択モード」の引数を使っていない。中ハーネス側の文言だけ合わせて直した。 確認済み
図の描画ライブラリは任意にした: 前は外部スキル diagram-design のインストールを求めていた。後は「あれば従う、無ければ同梱の最小ルール」に変え、インストールを求めない。 確認済み
実案件での使い勝手はまだ試していない: 見本はこのページだけ。次に本物の判断待ち (プラン確認や実装レビュー) で使ったときに、手引きの過不足が出る可能性がある。 未確認
