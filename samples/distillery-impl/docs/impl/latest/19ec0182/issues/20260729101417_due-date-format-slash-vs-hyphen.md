# tier-frontend.md 内で返却期限の表記が「YYYY/MM/DD」と「YYYY-MM-DD」で食い違う

- stage: S4 tier-impl (tier-frontend)
- 検出日時: 2026-07-29
- 深刻度: 非 blocker(実行可能な BDD を正として実装済み)

## 仕様の記載

`docs/specs/latest/貸出管理業務/貸出管理フロー/書籍を貸出する/tier-frontend.md` 内に
返却期限の表記が 2 箇所ある:

1. 表示要素とコンポーネントマッピング表「返却期限表示 | テキスト | - | 「返却期限: YYYY/MM/DD」」
   および操作フロー「4. 成功 → 「貸出が完了しました。返却期限: YYYY/MM/DD」表示」
   → **スラッシュ区切り**
2. ティア完了条件(BDD) Scenario「貸出完了後の表示」の Then 句
   「貸出が完了しました。返却期限: 2026-04-26」が表示される
   → **ハイフン区切り**

## 実装で判明した事実

同一メッセージ(貸出完了時の表示文言)について、プロース(表示要素表・操作フロー)と
実行可能な gherkin(ティア完了条件)とで区切り文字の表記が矛盾している。

## 実装での対応

test-strategy.md の転写ルールにより、ティア完了条件の gherkin は「意訳・要約・補完を禁止」
かつゲート 4(tier BDD)の判定根拠そのものであるため、gherkin の例文(ハイフン区切り)を正として
`formatDateHyphen`(貸出完了メッセージ用)を実装した。プロース側で言及されている
「予定返却期限(今日 + 14日)」の事前表示(貸出前のプレビュー、gherkin では未検証)は
プロースの記載どおりスラッシュ区切り(`formatDateSlash`)のまま実装している
(`frontend/src/components/loanConfirmation.ts` 参照)。

## 提案

- 仕様(spec.md 生成元)側で表記をどちらかに統一することを推奨する。実運用上は
  「貸出前のプレビュー」と「貸出完了後の確定表示」が異なる区切り文字になっている状態であり、
  UI として不自然(ユーザー体験として気づきにくい不整合)なため、本来は仕様定義時点で
  統一されるべき
