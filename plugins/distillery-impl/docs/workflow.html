distillery-impl plugin

dist-impl-run のワークフロー: UC 指定 → 実装完了までの状態機械

オーケストレータ(dist-impl-run)は状態ファイルの読み書きと dispatch だけを行い、重い仕事はすべて fresh サブエージェントに委譲します(コンテキスト 25% 制約)。git commit はオーケストレータのみ(単一コミッタ)。

🎛 オーケストレータが直接実行 🤖 サブエージェントに委譲 🤖×N tier ごとに並列委譲 💬 ユーザー対話ポイント 📄 書かれる状態ファイル(docs/impl/)

起動オーケストレータ
lease 確認 → UC 解決 → model 解決 → 再開判定
① run-lease があれば起動拒否(多重起動防止) ② UC 指定(完全修飾 / uc_id / 一意名)を uc-map と NFC 照合。複数一致は候補提示 ③ Implementer / Verifier の解決済み model を記録、同一なら停止して確認 ④ done ファイル + 入力ハッシュ再計算で「どの stage から再開するか」を決める

横断の仕組み

冪等再開(セッションが切れても巻き戻らない)

  • 完了の正は .done.yaml の存在 + manifest_sha256 一致。status.yaml は再構築可能なスナップショット
  • 再開時は入力ハッシュを現物から再計算し、変わった入力に依存する stage / bootstrap Phase だけを再実行
  • tier-scoped staleness: S4/S5 の done は自 tier の tier md だけを projection に含むため、spec の 1 tier 修正では他 tier の実装・検証は温存される(位置カスケードなし)
  • 中間生成物は削除しない。無効化は invalidated/ へ退避(イベント追記が先)

並走の安全(tier 並列でも壊れない)

  • stage ごとに明示的な write-set。サブエージェントは自分の領域しか書けない(逸脱 = stage failed)
  • git はオーケストレータのみ。stage 境界で git add -- <owned paths> → Conventional Commits(scope = uc_id)
  • packages/contracts・packages/ui は S4 中 read-only。書き換えを伴う format は barrier 後に単一 writer で実行
  • run-lease で多重起動を拒否
