# 将来の移行ガイドを追加する

1. 実際のリリース差分を確認し、出力が変わる版を`migration-catalog.md`へ追加する。修正作業中の予想をリリース済みの差分として登録しない。
2. 各変更に安定した項目IDを付け、導入版・変更前後・判断材料・修正方針・確認方法をガイドに書く。
3. 同じテーマの追記は新しい導入版の節へ分ける。過去の移行先に将来の仕様が混ざらないようにする。
4. 後続のガイドが以前の変更を置き換える場合、依存関係と最終形を明記する。中間ファイルを逐一生成することは要求しない。
5. 出力変更がないリリースも表に記録する。版の飛び越しに未調査の差分がないことを判断できるようにする。

新しい項目には次の観点を揃える。

| 項目 | 記載する内容 |
|---|---|
| 判断 | 実際の成果物のどこを読めば適用要否を決められるか |
| 修正 | LLMが比較・移動・再構成する情報。機械的に決められない点 |
| 保持 | 業務挙動、制約、ユーザー固有の記載、履歴のうち失ってはいけないもの |
| 確認 | 検証スクリプト、リンク・ID・意味の照合、完了条件 |
| 不足時 | 所有工程への提案やユーザー確認が必要になる具体的な状況 |

版を追加するときは、直前版からの移行と、複数版をまたぐ移行の両方で読む項目を確認する。
既に一部移行済みの入力、対象契約が存在しない入力、正本と本文に矛盾がある入力でも確認する。
実施例を残す場合は、どの版・項目を実際に適用したかと未検証範囲を記録し、ガイドが存在するだけの版を実行検証済みとしない。
