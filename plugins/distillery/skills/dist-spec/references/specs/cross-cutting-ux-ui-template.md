# 全体横断 Spec テンプレート定義（UX/UI）

> **読み込みタイミング**: Step2（全体横断 UX/UI 設計）/ Step4c（共通コンポーネント抽出）で使用。
> 全体横断 Spec の全体像（ディレクトリ構成・API/データストア概要）は `cross-cutting-template.md` を参照。
> トレーサビリティマトリクスのフォーマットは `cross-cutting-traceability-template.md` を参照。

UC 単位 Spec とは異なる粒度で、システム全体を俯瞰する UX/UI 設計仕様のフォーマットを定義する。

## ux-design.md フォーマット

> design 無しモード（`design_available: false`）では同じ節構成を使いつつ、「画面」をインターフェース種別に読み替える:
> ユーザーフローのノードはコマンド / API 呼び出し / ジョブ、サイトマップは「コマンド体系」（cli）/「リソース階層」（api）/
> 「ジョブ運用フロー」（batch）、ナビゲーション構造の表は「エントリポイント（サブコマンド / ルートリソース）」、
> アクセシビリティ方針は「非 TTY・スクリーンリーダー・色に依存しない出力」に置き換える。

## ui-design.md フォーマット（design 無しモード: 出力規約）

design-event.yaml が無い（UI 画面を持たない CLI / API / batch プロダクト）場合は、上記の代わりに次のフォーマットで生成する。
design-event.yaml・Storybook・コンポーネント名への参照を一切含めない。ファイル名は `ui-design.md` のまま。

下記は `interface_kind: cli` を基準にしている。`docs/rdra/latest/システム概要.json` の `interface_kind` に応じて節を差し替える:

| interface_kind | 差し替え |
|---|---|
| `cli` | 下記のまま |
| `api` | 「出力チャネル」→「レスポンス規約（成功/エラー時のボディ形状・エラーコード体系・ページング・バージョニング）」、「終了コード規約」→「HTTP ステータス規約」、「出力フォーマット」→「Content-Type / 日時・金額表記」。個々のエンドポイント定義は `openapi.yaml` に置き、ここでは横断規約だけを書く |
| `batch` | 「出力チャネル」→「ログ出力規約（レベル・構造化フォーマット・相関 ID）」、「終了コード規約」はジョブの終了コードとして残す、「出力フォーマット」→「成果物ファイル / 通知の形式」。スケジュール・再実行・冪等性は各 UC の非同期処理系ティアに書く |

```markdown
# 出力規約（UI 画面を持たないプロダクト）

## 出力チャネル

| チャネル | 用途 | 例 |
|---------|------|---|
| stdout | 正常な結果・データ（パイプ可能） | {例} |
| stderr | エラー・警告・進捗・診断メッセージ | {例} |

## 終了コード規約

| コード | 分類 | 条件 |
|-------|------|------|
| 0 | 成功 | {条件} |
| 1 | 汎用エラー | {条件} |
| 2 | 入力・引数エラー | {条件} |
| {n} | 業務エラー（{分類}） | {条件} |

## 出力フォーマット

- **既定**: {table / plain}。`--format json` で JSON（機械可読）
- **TTY 判定**: 非 TTY（パイプ）では色・装飾を出さない。`--no-color` / `NO_COLOR` を尊重する
- **JSON**: {スキーマの方針（キー命名、null の扱い、配列/オブジェクト）}
- **table**: {列順、ヘッダー、幅、日時・金額の表記}
- **ページング / 件数制限**: {`--limit` / `--offset`、大量出力時の振る舞い}

## メッセージ表現規約

- **エラー**: `error: {原因}` + 対処のヒント 1 行。原因は具体的な値を含める
- **警告**: `warn: ...`
- **進捗**: 長時間処理は stderr に進捗（TTY のみ）
- **多言語**: {日本語/英語の方針}

## 状態表示

| 状態モデル | 表示文字列 | 補足 |
|-----------|----------|------|
| {状態名} | {表示} | {色/記号を使う場合は非 TTY の代替} |

## アクセシビリティ・運用配慮

- 色だけで意味を伝えない（記号・文言を併用）
- スクリーンリーダー向けに 1 行 1 事実
- ログ・監査との整合（{方針}）
```

## data-visualization.md フォーマット

```markdown
# データ可視化設計仕様

## 可視化対象

| 画面 | 指標/データ | 用途 | チャート種別 |
|------|-----------|------|-----------|
| {画面名} | {表示するデータ} | {Comparison/Composition/Relationship/Distribution/Trend} | {推奨チャート} |

## チャート選定ガイドライン

（`references/specs/data-visualization-rules.md` を参照して適用する）

### 観点別チャート選定

| 観点 | 推奨チャート | 使用場面 |
|------|-----------|---------|
| Comparison（比較） | 棒グラフ、レーダーチャート | {具体的な場面} |
| Composition（構成比） | 円グラフ、積み上げ棒グラフ | {具体的な場面} |
| Relationship（関連性） | 散布図、バブルチャート | {具体的な場面} |
| Distribution（分布） | ヒストグラム、箱ひげ図 | {具体的な場面} |
| Trend（傾向） | 折れ線グラフ、エリアチャート | {具体的な場面} |

## ダッシュボード設計原則

### 情報の階層化

- **全体サマリー**: {KPI一覧、概要指標}
- **ドリルダウン**: {詳細データへの遷移方式}
- **フィルター**: {絞り込み条件}

### データストーリーテリング

- **ナラティブ**: {データから伝えたいメッセージ}
- **比較軸**: {前年比/目標比/他社比}
- **アクション**: {データを見た後に取るべきアクション}

## 認知負荷への配慮

- ワーキングメモリの限界（4-5項目）を考慮した情報量設計
- Data-Ink Ratio を意識した装飾の排除
- ゲシュタルトの法則に基づくグルーピング
```

## 注意事項

- 全体横断 Spec は RDRA モデルの全 UC を俯瞰して記述する
- ユーザーフローは業務フロー横断で描く（UC 単位ではない）
- デザインシステム（design-event.yaml）のコンポーネント・トークンを積極的に参照する（design 無しモードでは参照しない）
- UX 心理学原則の適用は `references/specs/ux-psychology-glossary.md` から選定する
- データ可視化ルールは `references/specs/data-visualization-rules.md` に従う
