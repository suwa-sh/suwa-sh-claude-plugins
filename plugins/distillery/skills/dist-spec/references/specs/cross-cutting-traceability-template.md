# 全体横断 Spec テンプレート定義（トレーサビリティマトリクス）

> **読み込みタイミング**: Step4d（トレーサビリティマトリクス + 網羅率是正）で使用。
> 全体横断 Spec の全体像は `cross-cutting-template.md`、UX/UI フォーマットは `cross-cutting-ux-ui-template.md` を参照。

## traceability-matrix.md フォーマット

RDRA で定義した全要素が Spec にどう落ちたかのトレーサビリティマトリクス。要件網羅率の算出根拠となる。

```markdown
# 要件トレーサビリティマトリクス

## 網羅率サマリー

| カテゴリ | 全要素数 | カバー済み | 未カバー | 網羅率 |
|---------|:-------:|:--------:|:------:|:-----:|
| 情報の属性 | {数} | {数} | {数} | {%} |
| 条件 | {数} | {数} | {数} | {%} |
| バリエーションの値 | {数} | {数} | {数} | {%} |
| 状態遷移パス | {数} | {数} | {数} | {%} |
| 外部システム連携 | {数} | {数} | {数} | {%} |
| **合計** | **{数}** | **{数}** | **{数}** | **{%}** |

## 要素と対応先

| 要素 | 対応状況 | [{UC1名}]({UC1パス}/spec.md) | [{UC2名}]({UC2パス}/spec.md) | {全UCの列} |
|------|------|---------------------------|---------------------------|------------|
| {情報名 / 属性名} | linked | [{対応箇所}]({根拠ファイル}) | | |
| {状態モデル / 遷移元 / 遷移先} | linked | | [{対応箇所}]({根拠ファイル}) | |
| {未対応の要素} | unlinked | | | |

全カテゴリの要素を行、全UCを列に並べた単一の表にする。
セルには `_trace-links.json` のanchor（対応箇所）を表示し、fileへリンクする。
同じ要素・UCに複数の対応箇所がある場合はセル内を `<br>` で区切る。
空欄は対応記録なしを表し、適用対象外と断定しない。
対応状況列のlinkedは少なくとも1つのUCに対応記録があることを示す。意味上の充足や実装完了とは区別する。
UCは契約catalogの順に並べる。同名UCは業務/BUCを含めて区別する。

## 未カバー要素一覧

要件網羅率が 100% に達していない場合、未カバー要素を一覧表示する。レビュー対象として優先的に確認する。

| カテゴリ | 要素 | 想定される理由 | 対応方針 |
|---------|------|-------------|---------|
| {カテゴリ} | {要素名} | {未カバーの理由} | {要対応/意図的除外/RDRA見直し} |
```

## 網羅率の算出ルール

- **分母**: RDRA の TSV ファイルから機械的に抽出できる全要素
  - 情報の属性: 情報.tsv の属性列をカンマ分割した個数
  - 条件: 条件.tsv の行数
  - バリエーションの値: バリエーション.tsv の値列をカンマ分割した個数
  - 状態遷移パス: 状態.tsv で「遷移UC」が非空の行数
  - 外部システム連携: 外部システム.tsv の行数
- **分子**: 関連 RDRA モデル・業務ルール・状態遷移に記録された要素から、適用 tier と具体的な実装/契約箇所を辿れるもの。
  情報属性は `_model-summary.yaml` の対象列や API schema/property への対応で検証する。
- **カバー判定**: 名前の列挙や参照の存在だけでは covered としない。参照先の対象要素・値・遷移が実在し、
  適用箇所と必要な BDD が確認できること。旧形式の分岐条件・計算・バリエーション一覧も同じ基準で読む。
- 図や BUC の CRUD 表の有無は網羅率に影響させない。参照は対象ファイルの見出し / ID / schema / table まで指定する。

## 注意事項

- traceability-matrix.md は全 UC Spec + BUC Spec が出揃った後に生成する
