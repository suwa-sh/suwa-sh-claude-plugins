# 解析対象と読み方

既存プロジェクト（リポジトリ）から RDRA モデル要素を逆生成するために、どの資産を・どの順で・
何を読み取るかを定義する。本ファイルは全 Phase 共通の前提知識であり、各 Phase のサブエージェントは
まず本ファイルを読み込んでから担当フェーズの逆生成を行う。

> 由来: `claude-code-rdra-rev`（RDRA リバース分析 v0.3.0）の分析対象定義を distillery の
> ディレクトリ構成に合わせて再編したもの。

## 解析対象の種類

優先度の高い順（＝事実としての確度が高い順）に読む。上位ほど「実装された事実」であり、
下位ほど「意図・背景の手がかり」である。

| # | 対象 | 具体例 | 主に読み取れる RDRA 要素 |
|---|------|--------|--------------------------|
| 1 | データストア定義 | マイグレーション（`db/migrate`, `prisma/schema.prisma`, `*.sql`）、ER 図、ORM エンティティ | 情報、状態、バリエーション、条件 |
| 2 | エンドポイント定義 | OpenAPI/Swagger、GraphQL Schema、gRPC `.proto`、ルーティング定義 | UC、画面、イベント、情報 |
| 3 | ソースコード（ドメイン層） | ドメインモデル、ユースケース/サービス、ステートマシン、バリデーション | UC、状態、条件、バリエーション、情報 |
| 4 | ソースコード（UI 層） | 画面コンポーネント、ページルーティング、フォーム | 画面、UC、アクター |
| 5 | 設定ファイル | 環境変数（`.env.example`）、権限/ロール定義、IAM、feature flag | アクター、外部システム、非機能要求 |
| 6 | 外部連携定義 | Webhook、メッセージキュー、cron/スケジューラ、SDK 初期化 | 外部システム、イベント、タイマー |
| 7 | テストコード | 単体・統合・E2E、シナリオテスト、fixture | UC、受け入れ基準、条件、バリエーション |
| 8 | ドキュメント | README、`docs/`、Wiki、ADR、仕様書 | 要求、業務、BUC、システム概要、技術スタック |
| 9 | コミット履歴 | `git log`、PR タイトル、CHANGELOG | 要求、理由（なぜ）、機能追加の経緯 |

## 読み方の原則

1. **事実を優先し、推測は明示する** — コード・定義から直接読めるものを「事実」として記録し、
   意図・背景（なぜ）はドキュメント／コミット履歴から探す。どちらからも読めない場合のみ推測し、
   `evidence-rules.md` に従って `confidence: low` を付ける。
2. **ID の単位で情報を捉える** — 情報（Information）は「ビジネス上管理される ID 単位」で存在する。
   テーブルの主キー・エンティティの識別子が情報の粒度の手がかりになる。
3. **状態は列挙型・ステータスカラム・状態遷移コードから読む** — `status`, `state`, `enum`,
   ステートマシン定義は状態モデルの直接的な証拠。
4. **バリエーションは区分・種別の列挙から読む** — `type`, `category`, `kind`, `role` 等の
   列挙値や区分マスタがバリエーション。
5. **アクターはロール・権限・認証境界から読む** — ロール定義、認可ミドルウェア、
   ログイン種別がアクターの手がかり。UI のメニュー分岐も参考になる。
6. **UC は「システムを使うまとまった作業」** — API エンドポイント 1 本が UC 1 個とは限らない。
   ユーザーの目的単位（例: 「蔵書を検索する」）でまとめる。
7. **大規模リポジトリはディレクトリ単位で分割** — コンテキストが溢れる場合はディレクトリ単位に
   分割して解析し、進捗を `checklist.md` に記録して中断再開する。

## モノレポ・複数リポジトリの扱い

- 入力が複数ディレクトリ（`./frontend ./backend` 等）の場合、UI 層とドメイン層を横断して
  同一の RDRA モデルに統合する。frontend は主に画面・アクター、backend は主に情報・状態・UC・外部連携の
  証拠源になる。
- サブシステム境界（マイクロサービス等）はコンテキスト（情報のグループ）の手がかりとして活用する。

## 解析対象の記録

逆生成の起点として、対象リポジトリのパスとコミットハッシュを `docs/harvest/events/{event_id}/sources.md`
に記録する。再解析・監査の再現性を確保するため、`git rev-parse HEAD` の値を必ず残す。
