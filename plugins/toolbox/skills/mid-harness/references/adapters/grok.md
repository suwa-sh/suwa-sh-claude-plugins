## 読込パス

| 面 | パス | 規則 |
|---|---|---|
| Instructions | `~/.grok/AGENTS.md` → `<repo>/AGENTS.md` → `<cwd>/AGENTS.md` (近いほど優先)。`CLAUDE.md` / `.claude/rules/` も互換読込 | `grok inspect` で実際に読まれた設定を確認できる |
| Skills | `.grok/skills/`、`.agents/skills/`、`.claude/skills/`、`.cursor/skills/` (repo と user)。優先度の高い場所が同名を上書き | `[compat.*]` で互換スキャンを止められる |
| Agents | `.grok/agents/*.md` (project)、`~/.grok/agents/` | front matter: `name` / `description` / `tools: [read_file, grep, ...]` / `permissionMode` |
| Hooks | `<project>/.grok/hooks/*.json`、`~/.grok/hooks/*.json`。Claude 互換 JSON。`.claude/settings.json` の hooks も互換読込 | **project hook は folder trust が必要** |
| Headless | `grok -p "<prompt>" --always-approve` | `-p` は `--single` の alias |

## Hooks

```json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash",
        "hooks": [ { "type": "command", "command": "../../scripts/agent-hooks/pre-tool-policy.sh  # mid-harness", "timeout": 10 } ] }
    ]
  }
}
```

- **command のパスは hook JSON ファイルのあるディレクトリ基準** (docs "relative to the configuration JSON file"、実測でも `.grok/hooks/` 基準)。`bash "$(git rev-parse --show-toplevel)/..."` の形にすれば cwd 非依存
- matcher は正規表現で **Grok 固有ツール名へ自動展開** される (`Bash` → `run_terminal_command`)
- stdin (実測 2026-09-05): camelCase と snake_case の両方が入る。`toolName: "run_terminal_command"`, `toolInput: {"command": ..., "description": ...}`, `cwd`, `workspaceRoot`, `permissionMode`, `hookEventName: "pre_tool_use"`
- ブロック: **exit 2**、または stdout `{"decision": "deny", "reason": "..."}`。その他の非ゼロは fail-open (ログのみ)
- trust: project hook は `/hooks-trust` (TUI) か `--trust` 起動フラグで folder を trust するまで**黙って飛ばされる**。trust は `~/.grok/trusted_folders.toml` の `[folders."<abs path>"] trusted = true` に記録される (MCP / LSP と共通)

### 論理イベント → 製品イベント

Claude Code と同じ (`PreToolUse` / `PostToolUse` / `SessionStart` / `Stop`)。

### gen_adapters の管理範囲

`.grok/hooks/mid-harness.json` を丸ごと所有する (このファイルだけ生成・削除)。他の `.grok/hooks/*.json` は触らない。

## Skills

`.agents/skills/` を直接読むため生成不要。`.claude/skills/` も読むので、Claude 向け生成物があると同名 skill が二重に見える (優先度で片方が勝つ)。

## Agents

`.grok/agents/<name>.md`:

```md
---
name: reviewer
description: <policy.description>
tools:
  - read_file
  - grep
  - list_dir
permissionMode: plan
---
<!-- generated by mid-harness from .agents/agent-specs/reviewer; do not edit -->
<prompt.md 本文>
```

### capability → tools

| capability | tools |
|---|---|
| read | `read_file`, `grep`, `list_dir` |
| edit | `search_replace` |
| shell | `run_terminal_cmd` |
| delegate | 個別制御なし → note |
| network | `web_search` |

tool ID は xai-grok-agent README の template 変数 (`${{ tools.read_file }}` / `search_replace` / `run_terminal_cmd` / `grep` / `list_dir` / `web_search` など) から転記。hook の stdin に現れる `toolName` は `run_terminal_command` で、agent 定義の tool ID (`run_terminal_cmd`) と表記が違う点に注意。README は全ツールを網羅していないため、未掲載のツールは書かない。未知の front matter は silently ignored。5 能力すべて true なら `tools:` を書かない。`edit` と `shell` が false なら `permissionMode: plan` (値は `default` / `acceptEdits` / `dontAsk` / `plan`)。

## 受け入れテストでの注意

- verify は folder trust が無いと hook テストが「発火しない」で fail する。`~/.grok/trusted_folders.toml` に対象 repo を足すか、対話で `/hooks-trust`
- `--always-approve` が無いと headless で承認待ちになる
