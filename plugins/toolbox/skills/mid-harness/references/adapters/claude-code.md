## 読込パス

| 面 | パス | 規則 |
|---|---|---|
| Instructions | `CLAUDE.md`、`.claude/CLAUDE.md`、`~/.claude/CLAUDE.md` | 起動時に親階層を読み、子階層はアクセス時に遅延読込。`@path` で他ファイルを起動時に展開 import できる (バッククォートで囲むと literal) |
| Skills | `.claude/skills/<name>/SKILL.md` (起動ディレクトリから repo root までの各階層)、`~/.claude/skills/`、plugin の `skills/` | **`.agents/skills/` は読まない。** サブディレクトリの skill はそのディレクトリのファイルを触ったとき遅延ロード。コマンド名はディレクトリ名 |
| Agents | `.claude/agents/<name>.md`、`~/.claude/agents/` | 既存ディレクトリ内の追加・編集は live reload される。起動時にディレクトリ自体が無かった場合は作成後に再起動が必要 |
| Hooks | `.claude/settings.json`、`.claude/settings.local.json` (gitignore)、`~/.claude/settings.json` | 配列設定はスコープ間で結合。local > project > user |
| Headless | `claude -p "<prompt>" [--output-format text\|json]` | print mode。hooks は有効 |

## Hooks

```json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash",
        "hooks": [ { "type": "command", "command": "bash \"$CLAUDE_PROJECT_DIR/scripts/agent-hooks/pre-tool-policy.sh\"" } ] }
    ]
  }
}
```

- stdin に JSON (`tool_name`, `tool_input.command` など)
- **exit 2 + stderr でブロック** (JSON の allow より優先)。exit 0 は通常フロー
- handler type は `command` のほか prompt / agent / http / MCP tool があるが、共通化するのは `command` だけ
- `$CLAUDE_PROJECT_DIR` はプロジェクトルート。hook の command はこれで絶対化する (cwd 依存を避ける)

### gen_adapters の管理範囲

`.claude/settings.json` の `hooks.<Event>[].hooks[]` のうち、`command` が所有 ID `  # mid-harness` で**終わる** handler だけを差し替える (部分一致ではない)。同じ group の他の handler、他の group、`permissions` 等の他キーは触らない。

生成はすべて一時ディレクトリで行い、unmappable / 未所有ファイル / TOML 不正が 1 つでもあれば何も書き込まない。

## Skills

`skills_mode`:

- `generate`: `.agents/skills/<name>/` を `.claude/skills/<name>/` へ**コピー**し、`.mid-harness-generated` マーカーを置く。マーカーのあるディレクトリだけを再生成・削除する
- `symlink`: `.claude/skills/<name>` → `../../.agents/skills/<name>` の相対 symlink。Claude Code が per-skill symlink を辿って skill を発見することは実測済み (2.1.261、2026-09-06)

どちらのモードも `.agents/skills/` 直下の**全ディレクトリ** (SKILL.md の無い、references だけの資料置き場を含む) を対象にする。skill から `../<name>/references/...` のように相対参照されている資料が、`.claude/skills/` 側でも同じ相対パスで解決できるようにするため。

front matter は `name` と `description` をそのまま使う (Claude Code の command 名はディレクトリ名なので `name` は一致させる)。

## Agents

`.claude/agents/<name>.md` (本文先頭に所有マーカー。マーカーの無い既存ファイルは `--adopt` 無しでは上書きしない):

```md
---
name: reviewer
description: <policy.description>
tools: Read, Glob, Grep
---
<!-- generated by mid-harness from .agents/agent-specs/reviewer; do not edit -->
<prompt.md 本文>

## 作業前に読む文書
- [docs/architecture/README.md](../../docs/architecture/README.md)
```

### capability → tools

| capability | tools |
|---|---|
| read | `Read, Glob, Grep` |
| edit | `Edit, Write, MultiEdit` |
| shell | `Bash` |
| delegate | `Agent` |
| network | `WebFetch, WebSearch` |

`tools:` は許可リスト。指定しないと親のすべてのツール (MCP 含む) を継承する。policy の 5 能力がすべて true のときは `tools:` を**書かない** (MCP ツールを絞ってしまうため)。1 つでも false なら true の能力に対応する tools だけを列挙する。`model` は policy が null なら書かない。`permissionMode` / `hooks` は生成しない。

`skills_mode: manual` のときは `.claude/skills/` に触らない (既存リポへ段階導入するとき用)。

## 受け入れテストでの注意

- `-p` でも project の hooks は有効。`.claude/settings.local.json` が同じイベントを持つと結合される
- skill 発見テストは `.claude/skills/` に生成物が無いと必ず fail する (上記 `.agents/skills` 非対応)
