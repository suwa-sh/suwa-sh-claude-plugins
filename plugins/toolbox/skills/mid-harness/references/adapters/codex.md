## Hooks

`.codex/hooks.json` は Claude Code と同じ形:

```json
{
  "hooks": {
    "PreToolUse": [
      { "matcher": "Bash",
        "hooks": [ { "type": "command", "command": "bash \"$(git rev-parse --show-toplevel)/scripts/agent-hooks/pre-tool-policy.sh\"  # mid-harness" } ] }
    ]
  }
}
```

- `matcher` は**正規表現** (`^Bash$` 等)。`Bash` でも部分一致で動く
- stdin に JSON (`session_id`, `cwd`, `hook_event_name`, `tool_name`, `tool_input`, …)
- **exit 2 + stderr でブロック** (sync hook のみ)。exit 0 で stdout が JSON なら block / updated_input を解釈。その他の非ゼロは "failed" 扱い (ブロックしない = fail-open)
- handler は `command` 型 (`command_windows` で Windows 用を上書き可)。`timeout` 秒指定可
- **tool_name はシェル実行で `Bash`** (Claude Code 互換の名前。実測 2026-09-05、codex-cli 0.145.0)。matcher `Bash` でよい

### hook の trust (最重要のハマりどころ)

- 非 managed の hook は**個別に trust hash** (`hooks.state."<source>:pre_tool_use:N:M".trusted_hash`) を持つ。状態は Trusted / Modified (hash 不一致) / Untrusted (未登録)
- **`codex exec` は Untrusted / Modified の hook を黙って飛ばす** (エラーも警告も出ない)。対話 TUI では review UI で trust する
- hooks.json を再生成して内容が変わると hash が変わり Modified に戻る
- 自動化で配線を検証するときは `codex exec --dangerously-bypass-hook-trust` (この invocation だけ trust review を省略)。`verify.sh` はこれを使う。運用では TUI で trust するか、`hooks.state` を `config/batchWrite` で書く
- project trust (`[projects."<path>"] trust_level = "trusted"`) は前提条件。無いと `.codex/` layer 自体が読まれない

### 命令パスの前提 (verified)

hook の `command` は **セッションの cwd** で実行される (`codex-rs/hooks/src/events/pre_tool_use.rs` が `request.cwd` を hook process の cwd に渡す)。project root とは限らない (サブディレクトリから起動すると相対パスは壊れる) ため、生成コマンドは実行時に root を解決する:

```
bash "$(git rev-parse --show-toplevel)/scripts/agent-hooks/<name>.sh"  # mid-harness
```

`.git` を project root marker にする Codex の既定 (`project_root_markers`) と一致する。git 管理外のディレクトリでは解決できないので、その場合は manifest 側で絶対パスを使う運用 (未実装) になる。末尾の `# mid-harness` は所有 ID で、gen_adapters はこの ID を持つ handler だけを差し替える。

### gen_adapters の管理範囲

`.codex/hooks.json` の `hooks.<Event>[].hooks[]` のうち、`command` が所有 ID `  # mid-harness` で**終わる** handler だけを差し替える (部分一致ではない)。同じ group に同居する他の handler は保持し、group が空になったときだけ group を消す。

## Agents

`.codex/agents/<name>.toml` (先頭行に所有マーカー `# generated by mid-harness …` を置く。マーカーの無い既存ファイルは `--adopt` 無しでは上書きしない):

```toml
# generated by mid-harness from .agents/agent-specs/reviewer; do not edit
name = "reviewer"
description = "<policy.description>"
developer_instructions = """
<prompt.md 本文 + 作業前に読む文書>
"""
sandbox_mode = "read-only"
```

`.codex/config.toml` には mid-harness 管理ブロックとして次を追記する (ブロック外は触らない):

```toml
# mid-harness:begin (generated — do not edit)
[agents.reviewer]
description = "<policy.description>"
config_file = "agents/reviewer.toml"
# mid-harness:end
```

`config_file` の相対パスは、それを定義する config.toml からの相対で解決される。

### capability → 設定

| capability | 変換 |
|---|---|
| read | 常に可 (制限しない) |
| edit | true → `sandbox_mode = "workspace-write"`、false → `"read-only"` |
| shell | Codex は shell tool を agent 単位で無効化できない (`sandbox_mode` は隔離方式の指定)。false を指定したら unmappable (fail / skip は policy の `on_unmappable`)。既定テンプレートの reviewer は `skip` で read-only sandbox だけ適用する |
| delegate | サブエージェント機能は `[agents] enabled` がグローバル。個別制御なし → false 指定は **note のみで生成は続行** (unmappable にはしない。既定テンプレートの reviewer が delegate=false のため) |
| network | true → `[sandbox_workspace_write] network_access = true` (edit が true のときのみ意味を持つ)。edit false + network true は unmappable |

`model` は policy が null なら書かない。

## 受け入れテストでの注意

- project を trusted にしていないと hooks も `.codex/config.toml` も読まれない (`~/.codex/config.toml` の `[projects."<abs path>"] trust_level = "trusted"`)
- hook 単位の trust が無い状態で `matcher: ""` (全ツール) の hook を置いて `codex exec` すると、実測でセッションが返ってこなかった (trust review 待ちと推定)。exec で試すときは `--dangerously-bypass-hook-trust` を付ける
- `codex exec` は `AGENTS.md` を root→cwd で連結する。サブディレクトリから起動すると追加の `AGENTS.md` が読まれる (指示衝突テスト #4 の対象)
