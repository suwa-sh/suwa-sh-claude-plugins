# adapter: Antigravity CLI (`agy`)

- 確認日: 2026-09-05
- 確認バージョン: agy 1.1.26
- 確認元: antigravity.google/docs (hooks, cli/commands/agents, cli/headless, cli/plugins, cli/mcp)、google-antigravity/antigravity-cli の _autodocs を Context7 / WebFetch で照合 + ローカル実測 (hook の探索と stdin、`--new-project`)

## 読込パス

| 面 | パス | 規則 |
|---|---|---|
| Instructions | `AGENTS.md` または `GEMINI.md` (workspace root)、`~/.gemini/GEMINI.md` | `.agents/rules/` も読む |
| Skills | `.agents/skills/<name>/SKILL.md`、`~/.gemini/config/skills/` | ネイティブ。生成不要 |
| Agents | `.agents/agents/<name>/agent.md` (workspace)、`~/.gemini/config/agents/<name>/agent.md` | front matter: `name` / `description` |
| Hooks | `.agents/hooks.json` (workspace)、`~/.gemini/config/hooks.json` (global)、plugin の hooks.json | **workspace が project として登録され、かつ trusted であるときだけ読まれる** (下記) |
| Headless | `agy -p "<prompt>" --output-format text --dangerously-skip-permissions` | 既定ではシェル実行が soft-deny されるので permission skip か allow rule が要る |

## Hooks

```json
{
  "mid-harness": {
    "PreToolUse": [
      { "matcher": "*",
        "hooks": [ { "type": "command",
                     "command": "bash \"$(git rev-parse --show-toplevel)/scripts/agent-hooks/pre-tool-policy.sh\"  # mid-harness",
                     "timeout": 30 } ] }
    ]
  }
}
```

- top-level は **hook 名をキーにした map** (`{"<hook-name>": {"PreToolUse": [...], ...}}`)。イベントは `PreInvocation` / `PostInvocation` / `PreToolUse` / `PostToolUse` / `Stop` の 5 つ
- `matcher` はツール名 (glob、`*` で全ツール)
- **hook の cwd は hooks.json のあるディレクトリ** (実測: `.agents/`)。command は `git rev-parse --show-toplevel` で root を解決する
- stdin (実測 2026-09-05): `{"toolCall": {"name": "run_command", "args": {"CommandLine": "echo hi", "Cwd": "...", ...}}, "stepIdx", "conversationId", "modelName", "workspacePaths", "transcriptPath", "artifactDirectoryPath"}`。**イベント名は stdin に無い** (command の引数で渡す)
- ブロック: stdout `{"decision": "deny"}` (`allow` / `deny` / `ask` / `force_ask` / `deny_unless_prior_grant`)。pre-tool-policy.sh (JSON + exit 2 + stderr) で実測: agent 側に "Execution was prevented by the policy hook" と返り、ログに `JSON hook command stderr: BLOCKED …` が残る。exit 2 単独でブロックできるかは未分離 (**unverified**)

### workspace hooks が読まれる条件 (実測)

`loaded 0 named hooks from 0 hooks.json file(s)` になる原因は、**セッションが workspace の project に束縛されていない** こと。headless の `agy -p` は既定で default project (folderUri 無し) に束縛され、cwd が登録済み project でも自動選択されない。

- 初回: `agy -p "..." --new-project` で cwd を project 登録する (`~/.gemini/config/projects/<uuid>.json`。`name` は **ディレクトリの basename**、`projectResources.resources[].folderUri` は canonical パス)
- 以降: `agy -p "..." --project <project id>` で束縛する。名前 (basename) でも指定できるが重複し得るので、verify.sh は `~/.gemini/config/projects/*.json` から folderUri が repo に一致する project の ID を引いて渡す (公式 docs の `--project=<project_id>`)
- `~/.gemini/antigravity-cli/settings.json` の `trustedWorkspaces` に **canonical パス** (`/tmp/...` でなく `/private/tmp/...`) が入っている必要がある
- 束縛できると `.agents/hooks.json` と `.agent/hooks.json` の両方が読まれる (同名 hook は 1 つに束ねられる)

`--new-project` を繰り返すと同名 project が増える (実測で 3 つできた)。verify は `--new-project` を使わない。

### 論理イベント → 製品イベント

| 論理 | Antigravity |
|---|---|
| `pre-tool` | `PreToolUse` |
| `post-tool` | `PostToolUse` |
| `session-start` | (対応なし → unmappable。`PreInvocation` は各ターンの前で意味が違う) |
| `stop` | `Stop` |

manifest の `matcher: Bash` は `*` に読み替える (ツール名は `run_command` で、Claude 系の名前と一致しないため hook スクリプト側で判定する)。

### gen_adapters の管理範囲

`.agents/hooks.json` の top-level キー `mid-harness` だけを所有する。他のキー (他の named hook) は保持する。所有判定は「その値に含まれる全 command が所有 ID `  # mid-harness` で終わる」こと (値の中に独自キーを足すと製品側の parser を壊し得るため)。同名キーが手書きなら `--adopt` 無しでは失敗する。

## 受け入れテストでの注意

- 対象 repo を project 登録 + trust していないと hook テストは「発火しない」で fail する。verify.sh は登録済み project の ID を渡すだけで、登録はしない (ユーザー設定に project を増やさない)。事前に一度 `agy -p "reply OK" --new-project` を対象 repo で実行し、`trustedWorkspaces` に canonical パスを入れておく
- skill 発見テストは `--project` 無しでも通る (skills は workspace から直接読まれる)
- `--dangerously-skip-permissions` が無いと headless で shell が soft-deny される
