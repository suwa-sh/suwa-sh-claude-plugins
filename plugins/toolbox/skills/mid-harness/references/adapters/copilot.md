## Hooks

```json
{
  "version": 1,
  "hooks": {
    "preToolUse": [
      { "type": "command",
        "bash": "bash \"$(git rev-parse --show-toplevel)/scripts/agent-hooks/pre-tool-policy.sh\"  # mid-harness",
        "powershell": "…",
        "timeoutSec": 30 }
    ]
  }
}
```

- イベント名は camelCase: `sessionStart` / `sessionEnd` / `userPromptSubmitted` / `preToolUse` / `postToolUse` / `agentStop`
- stdin (user hook で実測 2026-09-05): `{"sessionId", "timestamp", "cwd", "toolName": "bash", "toolArgs": {"command": ..., "description": ...}}`。docs は `toolArgs` が **JSON 文字列** の場合があるとする (両方を受ける)
- hook の cwd は実測でプロジェクト cwd。`cwd` フィールドで上書き可
- ブロック: stdout `{"permissionDecision": "deny", "permissionDecisionReason": "..."}`。**exit 2 も deny** (stdout JSON はマージ)。preToolUse ではその他の非ゼロ exit も deny (fail-closed)。timeout だけ fail-open
- **`-p` では repo hook が既定で無効** (セキュリティ目的)。有効化は 2 通り: ① repo 単位 = `~/.copilot/settings.json` の `trustedFolders` に repo の絶対パスを追加 (ユーザー側の設定。実測で変数なしでも発火)、② invocation 単位 = `GITHUB_COPILOT_PROMPT_MODE_REPO_HOOKS=true`。repo 内のファイル (`.env` 等) で有効化する経路は無い。1.0.83 で未コミットの生成 hook が発火し、番兵コマンドを拒否することを両経路で実測した。原因・比較結果・出典は [copilot-repo-hook-issue.md](copilot-repo-hook-issue.md)。

### 論理イベント → 製品イベント

| 論理 | Copilot |
|---|---|
| `pre-tool` | `preToolUse` |
| `post-tool` | `postToolUse` |
| `session-start` | `sessionStart` |
| `stop` | (対応なし → unmappable。`agentStop` は「ツール呼び出し後の継続判定」で意味が違う) |

manifest の `matcher` は hook entry の `matcher` に渡す (公式 hooks reference: `toolName` 全体に `^(?:PATTERN)$` で照合する正規表現、例 `"bash|edit"`。無効な正規表現は entry ごと skip)。Claude 名 `Bash` は `bash|powershell` に読み替える。

### gen_adapters の管理範囲

`.github/hooks/mid-harness.json` を丸ごと所有する。他の `.github/hooks/*.json` は触らない。

## Agents

`.github/agents/<name>.md`:

```md
---
name: reviewer
description: <policy.description>
tools: [read, search]
---
<!-- generated by mid-harness from .agents/agent-specs/reviewer; do not edit -->
<prompt.md 本文>
```

front matter は公式の custom-agents-configuration に従う: `name` (任意) / `description` (必須) / `tools` / `model` / `target` / `disable-model-invocation` / `user-invocable` / `mcp-servers` / `metadata`。`tools` は省略で全ツール、空リストで全ツール無効。

### capability → tools (公式 alias)

| capability | alias |
|---|---|
| read | `read`, `search` |
| edit | `edit` |
| shell | `execute` (互換名 `shell` / `Bash` / `powershell`) |
| delegate | `agent` |
| network | `web` |

5 能力すべて true なら `tools:` を書かない。`model` は policy が null なら書かない。

## 受け入れテストでの注意

- `--allow-all-tools` が無いと headless でツール承認待ちになり実行されない
- `verify.sh` は Copilot 起動時だけ `GITHUB_COPILOT_PROMPT_MODE_REPO_HOOKS=true` を付与する (検証用の invocation なので trust 状態に依存させない)。運用で repo hook を常時使う repo は `trustedFolders` に入れる。CI は環境変数。グローバルな export はしない (未知の repo の hook が黙って動く)
