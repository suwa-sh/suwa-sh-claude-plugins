# 図解: 何をどう描くか

図は飾りではない。**文章で読むより速く理解できる時だけ**描く。ただし迷ったら描く。目安は見出し 2 つにつき図 1 つ以上。

## 図の型と使いどころ

| 読者の問い | 型 | 描き方の要点 |
|---|---|---|
| いま全体のどこ? | 現在地マップ | 段階を横に並べ、現在地を 1 つだけ強調。済んだ段階は薄く |
| どう流れる? | フローチャート | 上から下、または左から右。分岐は菱形ではなくラベル付きの矢印 |
| 何が何とつながる? | 構成図 | 箱 = 部品、線 = 依存。変わった箱を強調 |
| 前と後で何が違う? | 前後ペア | 同じレイアウトを左右に並べ、差分だけ強調 |
| 案はどう違う? | 象限図 / 並列図 | 2 軸で位置づける。軸名を必ず書く |
| 状態はどう変わる? | 状態遷移図 | 状態 = 角丸の箱、遷移 = 矢印 + きっかけ |
| 誰が何をする? | スイムレーン | 横帯 = 役割、箱 = 作業、矢印 = 受け渡し |
| どのくらい? | 棒グラフ | 数値を棒の横に書く。軸目盛りは最小限 |
| 何が何に対応する? | 対応図 | 左右 2 列、線で結ぶ。多対多が多ければ表にする |

## 現在地マップ (ほぼ毎回使う)

「いまどこ」を 1 枚で見せる。

```text
[要望整理] → [設計] → [★ 実装 ← いまここ] → [テスト] → [公開]
   済         済        止まっている          未         未
```

- 段階は 3〜7 個
- 現在地だけをアクセント色 + 太枠 + 「いまここ」ラベル
- 止まっている理由を現在地の下に 1 行

## 前後ペア (変更のレビューで使う)

変更の理解は「前」と「後」を同じ形で並べるのが最速。

- 左に「前」、右に「後」。狭い画面では上下
- 変わった要素だけアクセント色。変わっていない要素は薄い灰
- 差分の要約を図の下に 3 行以内

## 複雑さの上限

超えたら 2 枚に分ける (全体図 + 拡大図)。

| 項目 | 上限 |
|---|---|
| 箱 | 9 |
| 矢印 | 12 |
| アクセント色の要素 | 2 |
| レーン | 5 |
| 状態 | 8 |

## 描き方の最小ルール (diagram-design が無い時)

`diagram-design` スキルがあれば、そのスタイルガイドと `references/type-*.md` に従う (外部フォントの link は入れない)。無ければ次に従う。

### 色 (base.html の CSS 変数と同じ)

| 役割 | 値 | 使う所 |
|---|---|---|
| 紙 | `#f7f5f0` | 背景 |
| 墨 | `#1f2328` | 文字、主要な線 |
| 灰 | `#6b7280` | 補足文字、通常の矢印 |
| 薄灰 | `#d6d3cc` | 済んだもの、対象外 |
| アクセント | `#c2410c` | 現在地、変わった所 (1〜2 個まで) |
| アクセント薄 | `#fde8dc` | アクセント要素の塗り |
| 青 | `#1d4ed8` | 外部とのやりとり |

### 形

- 箱: `rx="6"`、線幅 1、塗りは白
- 済んだ / 対象外の箱: 塗り `#f0eee9`、線 `#d6d3cc`、文字 `#6b7280`
- 現在地 / 変わった箱: 塗り `#fde8dc`、線 `#c2410c`、線幅 2
- 外部システム: 破線 `stroke-dasharray="4 3"`

### 矢印

- 直線か直角。斜めの線を引かない
- 曲がり角は `r=8` の円弧
- 矢印の先端は `<marker>` で定義する
- ラベルは線の上に 6px 以上離して置き、下に紙色の矩形を敷く
- 2 本の矢印を重ねない。同じ辺に 2 本入るなら 12px 以上離す

### 文字

- 箱の名前: 13px、太字、sans
- 補足: 10px、灰
- フォント: `"Hiragino Sans","Noto Sans JP",system-ui,sans-serif`
- 日本語の箱は幅を広めに取る (1 文字 13px + 余白 24px)

### 座標

- 4 の倍数に揃える
- 箱の間隔は 24〜48px
- `viewBox` は内容ぴったり + 余白 16px。`width="100%"` で親幅に合わせる

### スマホでの大きさ

図は親幅に合わせて縮む。390px の画面では図の表示幅が約 316px になり、viewBox 幅 960 の図では 13px の文字が 4px 台、560 の図でも 7px 台になって読めない。

| viewBox 幅 | 対応 |
|---|---|
| 400 以下 | そのまま (縮んでも 10px 以上を保てる) |
| 400 超 | `<figure class="fig scroll" style="--min: <viewBox 幅>px">` にする。狭い画面では横スクロールになり、設計どおりの文字の大きさを保つ |

現在地マップやフローチャートのような横長の図は、ほぼ `scroll` になる。縦に並べ直せる図 (前後ペア、状態遷移) は縦配置を優先し、viewBox 幅を 400 以下に収める。

## SVG の骨組み

```html
<figure class="fig scroll" style="--min: 960px">
  <svg viewBox="0 0 960 200" role="img" aria-labelledby="fig1-t">
    <title id="fig1-t">作業全体の流れと現在地</title>
    <defs>
      <marker id="ar" markerWidth="8" markerHeight="6" refX="7" refY="3" orient="auto">
        <polygon points="0 0, 8 3, 0 6" fill="#6b7280"/>
      </marker>
    </defs>
    <!-- 矢印を先に、箱を後に描く (線が箱の裏に回る) -->
    <line x1="176" y1="60" x2="216" y2="60" stroke="#6b7280" marker-end="url(#ar)"/>
    <rect x="16" y="32" width="160" height="56" rx="6" fill="#f0eee9" stroke="#d6d3cc"/>
    <text x="96" y="64" text-anchor="middle" font-size="13" font-weight="700" fill="#6b7280">要望整理</text>
    <!-- ... -->
  </svg>
  <figcaption>設計まで済み、実装の直前で止まっている。保存先を決めないと実装に入れない。</figcaption>
</figure>
```

- `<marker id>` は図ごとに一意にする (同じ id が複数あると先頭だけ効く)
- `<title>` は図の主張を 1 文で。`<figcaption>` は読者が受け取るべき結論を 1〜2 文で

## 図にしないもの

- 箱が 1 つしかない (文で書く)
- 一覧 (表かリスト)
- 3 列の表で同じことが伝わる (表)
