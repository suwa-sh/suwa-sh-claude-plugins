# 共通ルール (common)

全ティア共通のコーディング規約。実装時は `common.md` + 自ティアの `tier-<kind>.md` + `testing.md` の 3 つだけ読む。

## 必須 (Verifier が reject する違反)

1. **契約型の直接編集禁止**: `packages/contracts/` 配下 (契約からの生成物) を手で書き換えない。
   契約に不足があれば還流 (issues/) で契約の変更を要求する。再生成は d2-contract のみ。
2. **共通 UI 部品は `packages/ui/` のみ使用**: 新規コンポーネントの自作は禁止。不足は design への変更要求を経由する。
3. **仕様を実装側で曲げない**: 契約・ルールと実装が矛盾したら、実装を合わせるか issues/ に書く。
   「動くように契約と違うことをする」を禁止する。
4. **formatter / linter を通過する**: コマンドは `.distillery/config.yaml` の `commands` が正。
5. **Conventional Commits**: コミットは d2-run のみが行い、scope に UC slug を刻む。

## 推奨 (Verifier が指摘する品質基準)

- 関数・クラスは要求の用語 (RDRA の情報・状態・条件の名前) をそのまま使う。訳語・別名を発明しない。
- エラーは「利用者が直せる言葉」で返す。
- マジックナンバー・重複ロジックは、根拠となる契約・ルールへの参照コメントを付けて定数化する。
- 複数ティアが共有する算出規則 (hash 正規化・時刻精度・識別子形式) は、契約に定義されるまで実装で確定しない。
  仮置きが避けられない場合は 1 箇所に集約し、AssumptionRecord に記録する。
