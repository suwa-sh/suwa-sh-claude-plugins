# 決定候補カタログ: イミュータブルデータモデル

データを上書きで持つか、起きた事実を足していく形で持つかを決める。ADR の `scope: [data]`。データストアの決定 (data.md) と並べて書く。

---

## 方針

- **選択肢**: イミュータブル (事実を足す。今の状態は事実から求めるか、事実と別に持つ) / 一部イミュータブル (業務の事実だけ足し、マスタは上書き) / ミュータブル (上書き)
- **向く条件 (イミュータブル・一部)**: 状態の履歴を後から説明する必要がある (監査・取り消し・差し戻し)。同時の更新が多い (上書きの衝突を避けたい)
- **向く条件 (ミュータブル)**: 履歴が要らない設定値・マスタ

## 決めること

- **エンティティの分け方**: リソース (人・会議室など、持ち続けるもの) とイベント (予約した・取り消した など、起きたこと) を分ける。イベントは更新も削除もしない
- **今の状態の求め方**: イベントから毎回求める / 状態を別の表に持つ (イベントと同じトランザクションで更新する)
- **取り消しの表し方**: 行を消さずに、取り消したことのイベントを足す
- **日時**: 起きた時刻 (業務の時刻) と記録した時刻を分けて持つ

## 派生するルール例

```yaml
- scope: common
  text: "イベント (予約した・取り消した など) の表は追記だけ。UPDATE と DELETE をしない"
- scope: common
  text: "取り消しは行を消さず、取り消しのイベントを足す"
- scope: tier:backend
  text: "repository はイベントの表に更新・削除のメソッドを持たない"
```
