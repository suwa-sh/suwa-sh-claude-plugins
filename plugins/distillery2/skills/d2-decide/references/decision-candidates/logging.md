# 決定候補カタログ: ログのルール

何を・どの層で・どの形でログに出すかを決める。ADR の `scope: [app]`。エラーハンドリング (error-handling.md) と揃える。

---

## 決めること

- **形**: 構造化 (JSON の 1 行) / テキスト。運用で検索・集計するなら構造化
- **必ず持つ項目**: 時刻・レベル・メッセージ・相関 ID (1 つの要求を通して同じ)・UC やハンドラの名前・利用者の ID (個人情報でない識別子)
- **レベル**: error = 利用者の操作が失敗した・人が対応する / warn = 失敗したが自動で回復した / info = 業務のイベント (予約した など) と要求の始まりと終わり / debug = 開発のときだけ
- **層ごとの出す場所**: presentation = 要求の始まりと終わり・status・所要時間 / usecase = 業務のイベント / gateway = 外部とのやり取りの失敗・遅延 / domain = 出さない (イベントか戻り値で知らせる)
- **出さないもの**: 個人情報 (氏名・メールアドレス・電話番号)・秘密 (パスワード・トークン)・要求と応答の本文の全体
- **計装との関係**: テストの計装 (packages/test-support の tracer) とは別。ログは運用のため、計装は as-built とテストのため

## 派生するルール例

```yaml
- scope: tier:backend
  text: "ログは構造化 (JSON の 1 行) で、時刻・レベル・相関 ID・ハンドラの名前を必ず持つ"
- scope: tier:backend
  text: "domain 層はログを出さない。業務のイベントは usecase が info で出す"
- scope: common
  text: "個人情報・秘密・要求と応答の本文の全体をログに出さない"
```
