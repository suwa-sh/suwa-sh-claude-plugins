# 決定候補カタログ: ティア構成

プロダクトの形から、どのティア (frontend / backend-api / worker / API Gateway / IdP) を置くかを決める。
ベンダーニュートラルに書く (FaaS / CaaS / RDB のような汎用語)。ADR の `scope: [system]`。
ティア構成と各ティアの依存方向を決める ADR には**ティア間**の `arch_test` を最低 1 つ付ける (`level: tier`。プランの必須要件)。
ティア間規則の例 (frontend はバックエンドの内部実装へ直接依存せず、契約経由で呼ぶ):

```yaml
- scope: common
  text: "frontend は backend-api の内部実装へ直接依存してはならない (契約経由で呼ぶ)"
  arch_test:
    from: "apps/frontend/**"
    to: "apps/backend-api/src/**"
    effect: forbid
    level: tier
```

レイヤ内の依存規則 (`level: layer`) は [app-layers.md](app-layers.md) 側で付ける。

---

## backend-api (常に必要)

- **選択肢**: モジュラモノリス API / ドメイン別分割 API
- **向く条件 (モノリス)**: BUC 5 業務以下・単一ドメイン・同時アクセス小 (NFR B.1.1 Lv2 以下)。
- **向く条件 (分割)**: BUC 6 業務以上で独立した境界づけられたコンテキストがある。可用性 A>=Lv3 で個別スケールが要る。
- **向かない (分割)**: 1 館規模・小トラフィックでの早すぎる分割は運用コスト過多。
- **派生するルール例**:
  ```yaml
  - scope: common
    text: "backend-api は単一デプロイ単位のモジュラモノリスとし、業務モジュール境界を跨ぐ直接 import を禁じる"
  ```

## frontend

- **選択肢**: あり (SPA / SSR) / なし (API のみ)
- **向く条件**: アクター.tsv に社外アクター、または画面操作を伴う UC がある。アクター種別が 2 種以上なら利用者向け / 管理者向けの UI 分離を検討 (NFR E.5.3 のアクセス経路分離とも整合)。
- **tech の目安**: モバイル / SEO 要件があれば SSR/SSG、なければ SPA。
- **向かない**: バッチ専用・システム間連携のみのプロダクトには置かない。
- **派生するルール例**:
  ```yaml
  - scope: tier:frontend
    text: "利用者向けと管理者向けの UI は別アプリに分離し、認証経路を共有しない"
  ```

## worker (非同期 / 定期)

- **選択肢**: あり (定期バッチ / メッセージ駆動) / なし
- **向く条件**: BUC に「タイマー / 自動 / 定期 / バッチ / 一括」を含む、または状態遷移にタイマー起動がある (→ 採用の確信度 high)。「通知 / メール送信」は非同期 worker (medium)。
- **形態**: 定期のみ = スケジューラ + worker、非同期メッセージ = MQ + worker、両方 = 併用。
- **向かない**: すべて同期 request/reply で完結し遅延許容が無い場合。
- **派生するルール例**:
  ```yaml
  - scope: tier:worker
    text: "worker は冪等に実装し、同一ジョブ ID の二重実行で副作用が重複しないようにする"
  ```

## API Gateway

- **選択肢**: あり / なし (backend-api で直処理)
- **向く条件**: 外部アクター 2 種以上 + OAuth2/OIDC、フロント 2 種以上、IP 制限 (NFR E.5.3)、WAF (NFR E.10) のいずれか。
- **向かない**: 社内のみ・単一フロントで該当なし → 置かず backend-api が直接受ける。

## IdP (認証基盤)

- **選択肢**: マネージド IdP / セルフホスト / 簡易認証 (置かない)
- **向く条件**: 外部アクター + OAuth2/OIDC が必要 (high)。詳細は [認証/認可カタログ](auth.md)。
- **向かない**: 社内のみで既存ディレクトリ認証を使う場合。

## イベント駆動の扱い

イベント駆動は独立ティアにせず、worker + MQ で表現する。判断は [メッセージングカタログ](messaging.md) を参照。
